Guided Lab — End-to-End Pipeline (capstone)

Trigger → matrix build → container push → OIDC auth → environment-gated GitOps hand-off. Ties Sessions 1–4 together. Companion to guides/module-19-guided-lab-end-to-end-pipeline.md.

19.1 What we are building (instructor-led; follow along in your own repo where access allows)

A change on main builds and tests the affected microservices, pushes images, authenticates to Azure keylessly, and hands off to Flux behind an environment approval gate.

1 · Triggerpush → main, path filter
2 · Matrix builddiscover → fromJSON
3 · Push imagedocker build → ACR
4 · OIDC loginzero stored credentials
5 · Env gatesstaging → production approvals
6 · GitOps hand-offmanifest ref bump → Flux

19.2 The workflow, stage by stage (each stage maps to the module that taught it)


  
The GitOps boundary (Module 11) is sacred. Actions builds and pushes; Flux deploys. The hand-off is manifest-only — no kubectl, no helm. That boundary is what keeps the migration scope clean.
