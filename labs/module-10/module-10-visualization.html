10.4 Reusable workflow vs composite action — the decision (ADO: template ≈ RW, task group ≈ composite)

  
Share a pipeline → reusable workflow. Share a step recipe → composite action. Click each case to see which tool fits.

Reusable workflow — full job with inputs/secrets/outputs, per-repo variation via with:

    
The same build+tag+push step-group inside many workflows
Composite action — a fixed sequence of steps packaged as a reusable action

    
A two-line run: repeated a couple of times
Leave it as a run: step — don't over-abstract

  

  






  
10.5 Migration playbook & Copilot checkpoint (review generated YAML — Module 05 guardrails)

  

    
1 · Inventorydiff the N copies; list every variation

    
2 · Design contractvariation → input; conditional → boolean input

    
3 · Build shared workflowin org/shared-workflows, with its own CODEOWNERS

    
4 · Wire callersthin caller: trigger + uses + with + secrets

    
5 · Delete driftremove per-repo copies

    
6 · Version & iteratetag v1 → canary @main → promote v2

  

  
Copilot: great at steps 2–4. Prompt: "Design a reusable workflow from these three drifted per-service copies — every variation becomes an input, declare REGISTRY_TOKEN in secrets, expose image tag as output. Then generate the thin caller for service checkout." Then apply the Module 05 checklist: does it declare secrets: in workflow_call? Are uses: refs pinned (not @main)? Does every composite run: have a shell:? Dry-run on a branch before promoting the tag.
